Use [release/KhaanephAssaultCruiser-1.1.0.zip](release/KhaanephAssaultCruiser-1.1.0.zip). Verify its [SHA-256](release/KhaanephAssaultCruiser-1.1.0.zip.sha256), extract it, and follow the included `INSTALL.txt`. The ZIP is the previously tested 1.1.0 archive; its bytes and checksum are preserved.

```powershell
# From the extracted KhaanephAssaultCruiser folder, with the game closed:
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 `
  -GamePath 'D:\SteamLibrary\steamapps\common\Deserts of Kharak'
```

Requires supported Windows x64 Steam build 12339551 and the Khaaneph DLC. No campaign unit transfer is intended. All multiplayer peers must use matching files; an actual peer synchronization test is still outstanding.

## Build from source

Use Windows PowerShell, the .NET Framework compiler at the path configured in `tools/build.ps1`, Python 3.10+, and your own installed supported game. Run these commands from this `example/` directory:

```powershell
# Verifies the included upstream loader archive and example ZIP,
# then extracts local build dependencies and runtime assets.
python -B tools/prepare.py

$gamePath = 'C:\Program Files (x86)\Steam\steamapps\common\Deserts of Kharak'
.\tools\build.ps1 -GamePath $gamePath
.\tools\verify.ps1 -GamePath $gamePath

# Optional: create a fresh local installer from your build and assets.
.\tools\package.ps1
python -B tools/archive-install-package.py
```

The compiled DLLs go to ignored `dist/`. The release ZIP already includes the runtime geometry/textures; preparation extracts them to ignored local asset paths so a code-only rebuild does not need Blender. No commercial game assemblies are downloaded or supplied: the compiler references your installation.

`src/Patcher.cs` verifies the original game assembly hash and inserts static hooks in memory. `src/Runtime.cs` owns registration/rosters/research; `src/ModelAssets.cs` handles the KAC2 payload and prefab/material lifecycle; `src/NativeVoices.cs` selects approved existing Khaaneph clips.

For the existing export tools, extract donor metadata/textures from your own installed game first. Install `UnityPy==1.25.4` in your Python environment and inspect `tools/export-model-donors.py`: its default game path is the standard Steam location and may need adjustment. The original local `work/resources/python_deps` override is optional; a normal installed UnityPy is also importable. Run:

```powershell
python -B tools/export-model-donors.py
$blenderPath = 'C:\Program Files\Blender Foundation\Blender 5.1\blender.exe'
& $blenderPath -b --python-exit-code 1 --python tools/verify-kitbash.py
& $blenderPath -b --python-exit-code 1 --python tools/export-runtime-model.py
```

The tested authoring version was Blender 5.1.0. Regeneration/fit scripts can overwrite the working model; understand their fixed collection/material/donor assumptions before using them on your own design. GLB/FBX are authoring exchanges; the game consumes the exported KAC2/PNG payload, not arbitrary GLB files.
